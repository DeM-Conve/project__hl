# Back up the homelab

Everything hl keeps is in the homelab folder:

```
~/homelab/
  hl.yml          your config: worth keeping in git
  data/<app>/     every app's named volumes, as plain folders
  .hl/            generated by hl on every command: no need to back up
```

The apps' own folders (code, compose files, their `.env` with secrets, bind mounts like
`./uploads`) are separate; back those up the way you back up your projects.

## A full backup

Copy the data while the apps are stopped, so databases are consistent on disk:

```sh
hl down                                       # stops every app and the proxy
cd "$(hl path)/.."
sudo tar -cpzf "homelab-$(date +%Y%m%d).tar.gz" \
  --exclude="$(basename "$(hl path)")/.hl" "$(basename "$(hl path)")"
hl up
```

`sudo` and `-p` because containers often own their files as other users; the archive keeps
owners and permissions. `rsync -a` to another disk works as well (also with `sudo`).

To keep downtime short, stop and copy one app at a time:

```sh
hl down my-app
sudo tar -cpzf "my-app-$(date +%Y%m%d).tar.gz" -C "$(hl path)/data" my-app
hl up my-app
```

## Databases

A copied database folder is only safe when the database was stopped. To back up without
stopping, use the database's own dump tool inside its container, for example:

```sh
hl ps my-app                                       # find the database container
docker exec hl-my-app-db-1 pg_dump -U postgres app > my-app.sql
```

Many apps ship a backup service of their own for this; hl runs it like any other service.

## Restore

```sh
hl down my-app
sudo rm -rf "$(hl path)/data/my-app"
sudo tar -xpzf my-app-20260101.tar.gz -C "$(hl path)/data"
hl up my-app
```

To restore the whole homelab on a new machine: install hl, extract the archive to the same path
as before, `hl init <that folder>` (it keeps the existing `hl.yml` and makes it the default), put
the app folders where `hl.yml` expects them, then `hl up`.

If you restore to a different path, compose may report that a volume "already exists" with
other options: the Docker volumes still point at the old folder. Remove them with
`docker volume rm hl-<app>_<volume>`; they are only pointers, the data is in `data/`.
